## Задача A

### Цель работы

### 1. Препроцессинг

Создан файл `simple.cpp` с исходным кодом из задания.

Для выполнения препроцессинга и подсчёта строк использованы команды:

```bash
g++ -E simple.cpp -o simple.i
wc -l simple.cpp simple.i
```

**Вывод команд:**

```bash

```

**1. Количество строк:** в исходном файле — 22, после препроцессинга — 1073.

**2. Что находится перед функцией `main` и почему:**

Перед функцией `main` находятся объявления из подключённых заголовочных файлов, служебные отметки препроцессора, а также глобальные переменные и функции исходной программы. Количество строк выросло, потому что препроцессор обработал директиву `#include <cstdio>` и вложенные подключения.

**3. Что произошло со строкой формата `printf`:**

Строка `"Result: %d, Counter: %d, Magic: %d\n"` осталась внутри вызова `printf` в функции `main`, препроцессор сохранил её без изменений.

### 2. Компиляция и оптимизации

Для получения ассемблерного кода без оптимизации и с оптимизацией использованы команды:

```bash
g++ -S -masm=intel -O0 simple.cpp -o simple_O0.s
g++ -S -masm=intel -O2 simple.cpp -o simple_O2.s
wc -c simple_O0.s simple_O2.s
```

Флаг `-S` останавливает сборку после получения ассемблерного кода, `-masm=intel` задаёт синтаксис Intel, `-O0` отключает оптимизации, а `-O2` включает их.

**Вывод команды подсчёта размеров:**

```text
2497 simple_O0.s
1692 simple_O2.s
4189 total
```

**4. Размер:** Размер файла с `-O0` составил 2497 байт, с `-O2` — 1692 байта. Отношение размеров: 2497 / 1692 ≈ 1,48. Оптимизированный ассемблерный файл примерно в 1,48 раза меньше, его размер уменьшился примерно на 32%.

**5. square:** Функция square обозначена меткой `_Z6squarei`. Для вычисления квадрата используется инструкция целочисленного умножения `imul eax, eax` - аргумент поступает в регистре `edi`, затем через память на стеке загружается в `eax`, и результат умножения возвращается в регистре `eax`.

**6. sum_of_squares:** Первый аргумент функции `sum_of_squares` - число 3 - передаётся в регистре `edi`, второй аргумент - число 4 - в `esi`. Это соответствует соглашению о вызовах System V AMD64 ABI, используемому в данном окружении Linux x86-64.

**7. Исчезание:** При оптимизации `-O2` отдельное определение функции square сохранилось, но её вызовы исчезли. В `sum_of_squares` компилятор встроил операции умножения непосредственно в тело функции. В `main` выражение `sum_of_squares(3, 4)` было вычислено на этапе компиляции и заменено константой 25. Определение `square` сохранено, поскольку функция имеет внешнее связывание и может вызываться из других единиц трансляции.


### 3. Ассемблирование

Для создания объектного файла и просмотра его символов использованы команды:

```bash
g++ -c simple.cpp -o simple.o
nm simple.o
```

**Вывод `nm simple.o`:**

```text
0000000000000000 B global_counter
000000000000005e T main
                 U printf
0000000000000044 T _Z12bump_counterv
0000000000000013 T _Z14sum_of_squaresii
0000000000000000 T _Z6squarei
0000000000000000 r _ZL5MAGIC
```

**8. Тип символа MAGIC:** Символ `_ZL5MAGIC` имеет тип `r`, так как константа `MAGIC` размещена в области данных только для чтения. Строчная `r` указывает на локальный символ - глобальная константа `const int MAGIC` в C++ по умолчанию имеет внутреннее связывание. Тип `D` обозначает изменяемые инициализированные данные, поэтому для `MAGIC` он не используется.

Для просмотра размеров использована команда:

```bash
size simple.o
```

**Вывод команды:**

```text
   text    data     bss     dec     hex filename
    400       0       4     404     194 simple.o
```

**9. Размеры секций:** Команда `size` показывает размеры областей кода и данных объектного файла в байтах. Больше всего места занимает категория `text` — 400 байт: она учитывает машинный код функций, данные только для чтения и служебные данные. Категория `data` занимает 0 байт, поскольку изменяемых данных, требующих хранения ненулевого начального значения, в программе нет. Категория `bss` занимает 4 байта для переменной `global_counter` типа `int`, изначально равной нулю. Для `bss` учитывается память, необходимая при запуске, а сами нулевые байты в объектном файле не хранятся. Столбцы `dec` и `hex` показывают сумму размеров: 404 байта в десятичной системе и 194 в шестнадцатеричной. Эта сумма не равна полному размеру файла `simple.o`, который также содержит заголовки, таблицу символов и другие служебные сведения.

### 4. Компоновка и запуск

Для компоновки объектного файла в исполняемую программу и её запуска использованы команды:

```bash

```

**Вывод программы:**

```text

```

**10. Результат запуска:** Программа вывела сумму квадратов чисел 3 и 4 — `25`, значение счётчика после одного вызова `bump_counter()` — `1` и значение константы `MAGIC` — `42`.


## Задача B

### 1. Раскрытие макросов и форматирование

Для раскрытия макросов выполнена команда:

```bash
gcc -E -P legacy.c -o legacy_expanded.c
```

Флаг `-E` выполняет препроцессинг, а `-P` убирает служебные отметки с именами файлов и номерами строк. Например, запись `P(F,main)(V)` после раскрытия макросов превращается в `int main(void)`.

На основе результата создан файл `legacy_manual.c`. Развёрнутое содержимое системных заголовков заменено исходными подключениями `<stdio.h>` и `<stdlib.h>`, функции оформлены с переносами строк и отступами, в объявлении счётчика функции `df` явно указан тип `int`. Перед функциями добавлены комментарии с предлагаемыми понятными именами, сами имена я решила сохранить.

### 2. Разбор алгоритма проверки

Функция `main` читает строку через `fgets`, вызывает `dc`, затем `df` и проверяет результат через `ch`. Нечётное число операторов `!` перед `ch(i)` равнозначно одному отрицанию: успешная проверка возвращает `0`, неуспешная - `1`.

Назначение функций установлено при чтении кода:

| Функция | Назначение |
|---|---|
| `z` | Добавляет узел в начало списка |
| `pi` | Считает длину списка; в программе не вызывается |
| `ip` | Создаёт список длины `n`, если `n > 0`, иначе пустой |
| `pc` | Возвращает `1`, если длины двух списков различаются, иначе `0` |
| `dc` | Копирует 1024 символа в массив целых чисел |
| `df` | Преобразует значения массива |
| `ch` | Сравнивает преобразованный ввод с эталоном |

В `dc` за один проход выполняются восемь присваиваний, а цикл повторяется 128 раз. В `df` за проход обрабатываются семь элементов: метки `case 6` и `case 5` ведут к одной операции. Поэтому `df` изменяет первые `7 × 128 = 896` элементов

### 3. Восстановление эталонных чисел и строки

Массив `a` в функции `ch` хранит списки, длины которых задают эталонные числа (e.g., `z(z(z(0)))` обозначает список длины 3). Cкриптом на питоне подсчитано количество вызовов `z` в каждом элементе массива.

Для восстановления кодов символов использованы обратные операции функции `df`. Нужная операция определяется остатком от деления индекса на 7:

| Индекс по модулю 7 | Преобразование кода `x` | Восстановление из результата `y` |
|---|---|---|
| 0 | `x ^ 99` | `y ^ 99` |
| 1 | `x ^ 48` | `y ^ 48` |
| 2 | `x << 4` | `y / 16` |
| 3 | `x << 2` | `y / 4` |
| 4 | `x * 55` | `y / 55` |
| 5 | `x + 97` | `y - 97` |
| 6 | `x + 44` | `y - 44` |

`5 ^ 99 = 102` соответствует символу `f`, `92 ^ 48 = 108` - символу `l`, а `1552 / 16 = 97` - символу `a`. Первые символы восстановлены вручную, затем повторяющиеся вычисления и перевод кодов в символы автоматизированы в скрипте`inspect.py`.
